# Payment

目标： 在 tg 的 mini app， pc、多端 h5 上实现对商品的购买，支持 eth 链 eth, usdt, usdc, tron 链 trx, usdt, usdc, ton 链的 usdt, ton 的支付

方式：

1. Aurpay 支付网关: 前端在购买时发起交易，后端通过 callback signature 验证调用的 aurpay api，获取不同链的 calldata, 然后返回给前端。前端进行私钥加签，加签数据和公钥地址发给后端，后端验证公钥和加签数据一致后，再发交易到 aurpay， 如果失败则发到标准代币合约的地址上，要记录交易数据
2. Aurpay 无法访问时，后端直接调用相应合约，构建 calldata，然后返回给前端，前端进行私钥加签，加签数据和公钥地址发给后端，后端验证公钥和加签数据一致后，再发交易到合约地址上。交易成功后，后端通过监听链上事件，来确认交易是否成功，然后返回给前端。同时要在数据库记录。
3. 后端无法访问时，前端直接调用合约，构建 calldata，然后进行私钥加签，直接发交易到链上。交易成功后，前端通过监听链上事件，来确认交易是否成功。同时发 txhash 和数据给后端，后端通过 txhash 来监听链上事件，来确认交易是否成功，然后返回给前端。同时要在数据库记录。

## 1. 使用 Aurpay 支付网关

- 流程总结：
  - 前端发起交易请求，后端通过 callback signature 验证 Aurpay API，获取链上 calldata。
  - 前端使用私钥对 calldata 进行签名，并将签名和公钥发送给后端。
  - 后端验证签名和公钥是否匹配，并发送交易到 Aurpay 处理。
  - 如果 Aurpay 处理失败，则将交易直接发送到代币合约地址。
- 关键点：
  - callback signature 验证：确保 callback signature 来自 Aurpay 的有效性，以保证 API 响应的数据未被篡改。
  - 交易回滚：当 Aurpay 无法处理时，后端能够回滚并选择直接通过标准代币合约处理交易，这个设计提高了系统的容错能力。
  - 交易记录：在数据库中记录每笔交易，确保后续可以追踪和处理失败交易或成功交易。
- 此流程没有问题，你保证了 Aurpay 和链上的支付互补性，确保了交易不会因单一通道失败而中断。

## 2. Aurpay 无法访问时，后端直接调用合约

- 流程总结：
  - 当 Aurpay 无法响应时，后端直接调用合约，生成 calldata 并返回给前端。
  - 前端私钥签名后将数据发回后端，后端验证后直接将交易发送到链上。
  - 交易成功后，后端通过监听链上事件确认交易是否成功，并记录交易。
- 关键点：
  - 后端生成 calldata：确保后端正确生成符合标准的 calldata，尤其是在不同链上（例如 Ethereum 和 TRON），生成逻辑需要严格遵循各链的标准。
  - 链上事件监听：通过监听链上事件（如 Transfer 事件或交易状态变更）来确认交易是否成功，这确保了后端能够准确捕捉交易结果，并将其返回给前端。
  - 数据库记录：对于成功和失败的交易，后端都需要在数据库中记录，确保后续可以回溯。
- 此流程没有问题，确保了在 Aurpay 无法访问的情况下，系统仍能正常处理交易。

## 3. 后端无法访问时，前端直接调用合约

- 流程总结：
  - 当后端无法访问时，前端直接调用链上合约，生成 calldata 并进行私钥签名，直接发送交易到链上。
  - 前端监听链上事件确认交易成功后，将 txhash 和交易数据发送给后端。
  - 后端通过 txhash 监听链上事件确认交易是否成功，并记录交易。
- 关键点：
  - 前端直接调用合约：确保前端能够正确生成 calldata，并能处理私钥签名和链上交易的提交流程。
  - 交易确认：前端和后端都可以通过链上事件监听确认交易结果，这种方式即使在后端无法访问时，也能保证交易成功后的追踪。
  - 交易记录：前端通过发送 txhash 和交易数据到后端，确保后端可以在恢复后继续监控交易状态，并记录交易数据。
- 此流程没有问题，确保在后端服务不可用时，交易依然能够完成，并且交易的状态可以在后端恢复后继续追踪和记录。

## 4. 总结

这三种方式是非常全面且稳健的支付设计方案。它们不仅涵盖了 Aurpay 支付通道的正常使用，还处理了当 Aurpay 和后端不可用时的异常情况。以下几点确保了流程的健壮性：

- 多重 fallback 机制：无论是 Aurpay 还是后端出现故障，流程都能确保交易顺利完成。
- 签名与验证：通过私钥加签和公钥验证，保证了每笔交易的真实性与安全性。
- 链上事件监听：通过链上事件监听，确保交易的结果能够被正确捕捉并反馈到前端。
